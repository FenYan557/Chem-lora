## 1. 任务目标与整体流水线

目标：从 PCQM4Mv2 的 337 万分子中挑出一个有代表性的子集（目标 5 万），用于数据集蒸馏 / 子集筛选研究。
方法路线：**embedding → 降维 → 密度聚类 → 每簇挑代表点**。

```
PCQM4Mv2  3,452,095 条 SMILES
      │   字段路径 labels.object.SMILES
      ▼
┌──────────── 三种 embedding（互为对比）────────────┐
│ MoLFormer-XL 768d │ ChemBERTa-77M-MTR 384d │ Morgan 2048bit │
└───────────────────────────┬─────────────────────────────────┘
                            ▼  L2 归一化（使欧氏距离 ≈ 余弦距离）
                    (可选) PCA → 100 维（仅预压缩）
                            ▼
                    UMAP → 15 维      (cuml, GPU)
                            ▼
                  HDBSCAN 密度聚类     (cuml, GPU)
                            ▼
     每簇按 sqrt(簇大小) 配额挑代表点：medoid + 最远点采样 + 少量噪声点
                            ▼
        subset.csv（含 smiles / cluster / role / strength）
```

## 2. 方法逻辑：为什么是这几步

**为什么先 embedding**：聚类的输入必须是能表达"分子相似性"的向量。SMILES 字符串本身没有度量意义，所以先用预训练模型把分子映射成稠密向量，让"结构/性质相近的分子在空间里靠得近"。

**为什么必须降维**：HDBSCAN 依赖"互达距离 + 密度"来划分簇。在 768 / 2048 维空间里，点对距离趋于同值（维度灾难），密度估计失效，结果要么碎成一地小簇，要么全被判成噪声。降到 15 维后局部邻域结构才可靠。

**降维不是"取最大奇异值"**：那是 PCA——线性变换、按方差（奇异值平方）排序、保全局距离。这里给 HDBSCAN 用的降维是 **UMAP**：非线性流形学习，先建 kNN 图（`n_neighbors=50`），再用模糊集合边权做低维布局，保的是**局部邻域关系**，正好匹配 HDBSCAN 的密度判据。代码里 PCA 只承担"维度太高时先压到 100 维"的预压缩角色。

**为什么 HDBSCAN 而不是 KMeans**：不需要预先指定簇数 k；能处理密度不均的数据；自带噪声标签（`-1`），天然把"孤例分子"识别出来。参数 `min_cluster_size=300`、`min_samples=10`。

**代表点怎么挑**：每簇取 1 个 medoid（到簇内所有点距离和最小 = 最能代表簇心）+ 若干最远点采样（覆盖簇内多样性）；名额按 `sqrt(簇大小)` 分配，避免大簇吃掉全部预算；另留 5% 名额给噪声点，防止子集丢失稀有骨架。

公式推导、复杂度分析和伪代码见同目录的 `HDBSCAN_子集筛选_实现逻辑.md`。

## 3. Embedding 选型（三种，全部免改模型代码）

| 模型 | 维度 | 规模 | 取向量方式 | 精度 | 实测速度 | 权重位置（服务器） |
|---|---|---|---|---|---|---|
| `IBM/MoLFormer-XL-both-10pct` | 768 | ~47M（187 MB） | `[CLS]` = `last_hidden_state[:,0,:]` | fp16 | **~1650 mol/s**（bs=128） | `embedding/molformer/code/MoLFormer-XL-both-10pct/` |
| `DeepChem/ChemBERTa-77M-MTR` | 384 | ~3.5M（14 MB） | `[CLS]` | fp16 | **~860 mol/s**（bs=256） | `embedding/chemberta2/code/ChemBERTa-77M-MTR/` |
| Morgan 指纹（ECFP4, r=2, 2048 bit） | 2048（稀疏，均值 30 个 1） | 无参数 | RDKit 位向量 → uint8 | — | **~16.8k mol/s**（8 进程 CPU） | 不需要权重 |

选型理由（对应"选适合 3090 跑的、尽量不改代码"这个要求）：

1. **都是现成权重 + 官方 API 前向**，不用改模型源码（MoLFormer 只需一个 20 行兼容 shim，见 §8 第 5 条）。
2. **单张 3090 24G 足够全量**：MoLFormer fp16 权重仅 ~94 MB，ChemBERTa 更小；瓶颈是时间不是显存。
3. **三种向量性质互补，正好构成对比实验**：MoLFormer = 大规模 SMILES 自监督（10% PubChem，线性注意力 + 双向）；ChemBERTa = 较小规模 MLM + 多任务回归；Morgan = 纯结构子图哈希，完全无学习。可以回答"embedding 质量对子集代表性影响有多大"。
4. **维度不同不是问题**（768 / 384 / 2048 都能进同一条聚类链路）：`cluster_subset.py` 先 L2 归一化 → PCA 到 `--pca-dim 100` → UMAP 到 15 维，输入维度任意。
5. Morgan 指纹生成走 **CPU / RDKit**，不占显卡，可与 GPU 任务并行。

## 6. 怎么跑（复制粘贴即可）

### 6.1 第 0 步：SMILES 缓存（已建好，重建加 `--force`）

```bash
cd /mnt/data/yangsensen/embedding
/mnt/data/yangsensen/envs/yangsensen/bin/python build_smiles_cache.py
```

### 6.2 第 1 步：小样验证（几分钟）

```bash
cd /mnt/data/yangsensen/embedding
LIMIT=2000 bash run_all.sh        # 每个分片只跑前 2000 条，JOBS=16 可改 Morgan 进程数
```

### 6.3 第 2 步：全量三种 embedding（双卡并行，务必 nohup）

```bash
cd /mnt/data/yangsensen/embedding
nohup bash run_all.sh > run_all.log 2>&1 &
tail -f molformer/output/molformer_shard0.log     # 日志里有 mol/s 和 ETA
```

`run_all.sh` 会自动：设好离线/缓存/临时目录环境变量 → 用绝对路径 python → MoLFormer 两卡分片（GPU0 跑 shard0/2、GPU1 跑 shard1/2）→ 同时 CPU 32 进程跑 Morgan → 等 MoLFormer 结束后 ChemBERTa 再上两卡（避免抢显存）。

单独跑某一个（例）：

```bash
cd /mnt/data/yangsensen/embedding/molformer/code
export HF_HOME=/mnt/data/yangsensen/hf_cache HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
CUDA_VISIBLE_DEVICES=0 /mnt/data/yangsensen/envs/yangsensen/bin/python \
    embed_molformer.py --shard 0 --num-shards 2
```

**公共参数**：`--shard / --num-shards`（按 `df.iloc[shard::num_shards]` 切分）、`--batch-size`、`--max-len`、`--limit`（只取前 N 条，冒烟用）、`--seed`。Morgan 专有：`--n-jobs`、`--no-packed`。

### 6.4 第 3 步：聚类出子集

```bash
cd /mnt/data/yangsensen/embedding
P=/mnt/data/yangsensen/envs/yangsensen/bin/python
$P cluster_subset.py --backend cuml \
   --emb  molformer/output/molformer_emb_shard0of2.npy \
   --meta molformer/output/molformer_smiles_shard0of2.csv \
   --outdir molformer/output --target 50000
```

| 参数 | 默认 | 含义 |
|---|---|---|
| `--backend` | auto | `cuml`(GPU) / `sklearn`(CPU) / `auto`（优先 cuml，缺则退化） |
| `--emb` | 必填 | embedding `.npy`，维度任意；多个文件用逗号分隔可一次跑多套 |
| `--meta` | 必填 | 与 emb **行对齐**的 CSV（含 `smiles` 列），用于回溯分子 |
| `--target` | 50000 | 目标子集大小 |
| `--fit-n` | 500000 | 只用这么多点拟合 UMAP+HDBSCAN，其余用 `approximate_predict` 分批打标（345 万全量必需） |
| `--chunk` | 200000 | 分批 transform / predict 的块大小 |
| `--pca-dim` | 100 | 高于该维度先 PCA 预压缩 |
| `--n-components` | 15 | UMAP 目标维度 |
| `--n-neighbors` | 50 | UMAP 邻域大小 |
| `--min-cluster-size` / `--min-samples` | 300 / 10 | HDBSCAN 核心参数 |
| `--noise-frac` | 0.05 | 噪声点名额占比 |
| `--top-m` | 100 | 簇内 strength 候选池 |
| `--seed` | 42 | 可复现 |

**输出**（每个 emb 一套）：`<name>_subset.csv`（选中行 + `cluster` + `role` + `strength`）、`<name>_labels_all.npy`（全库簇标签）、`<name>_run_config.json`（超参与统计，保证可复现）。

### 6.5 "聚类后能不能知道哪个分子属于哪个簇？" —— 能

每个 embedding 脚本都会**同时**落一个 `*_smiles_*.csv`，行序与 `.npy` 严格一一对应；`cluster_subset.py` 的 `--meta` 就吃这个文件，因此：

- `subset.csv` 直接带 `smiles` 列 + 它所属的 `cluster` 编号 + 被选中的 `role`（medoid / farthest / noise）；
- `labels_all.npy` 与输入 emb 同序，第 i 个分子的簇号就是第 i 个元素；
- Morgan 会丢弃 RDKit 解析失败的 SMILES，所以它单独落 `morgan_smiles.csv` 记录**保留下来的行**，对齐关系仍然成立。

### 6.6 质检脚本（本地 Windows）

`analyze_subset.py`（子集大小是否等于 target、重复率、簇覆盖、与"真实簇"的 ARI / NMI）、`eval_umap.py`、`probe_umap.py`、`probe_sklearn_hdbscan.py`、`time_one_config.py`（单组超参计时）、`make_test_data.py`（造 5000 条带真实簇标签的测试数据）。已有试跑产物在 `test_data/`、`test_subsets/`。

| 2 | pip 装包慢到超时 | pypi.org 实测 29 kB/s | 全部走清华 tuna 镜像 |

| 4 | pip 擅自升级 transformers 5.23 / numpy 2.4 / pandas 3.0 | rapids 依赖链拉动 | `revert_transformers.sh` 把 transformers 钉回 4.57.6；numpy/pandas 接受新版 |
| 5 | ChemBERTa 加载报错 | transformers ≥4.57 在 torch<2.6 下拒绝 `torch.load` 读 `.bin`（CVE-2025-32434） | 把 `pytorch_model.bin` 转成 `model.safetensors`（原 `.bin` 保留未删） |

| 7 | `RuntimeError: "geqrf_cpu" not implemented for 'Half'` | 直接传 `torch_dtype=float16`，MolformerFeatureMap 在 `__init__` 里于 CPU 上做 fp16 QR 分解 | `mol_io.load_fp16_model`：**fp32 在 CPU 构建 → `.half().cuda()`**，推理速度/显存不变 |
| 8 | `MolformerModel.forward() got an unexpected keyword argument 'token_type_ids'` | tokenizer 多返回一个字段 | 前向只传 `input_ids` / `attention_mask` |
| 9 | `RuntimeError: expected scalar type Float but found Half` | config 里 `deterministic_eval=false` → 每次 forward 都用 `torch.randn` 重新生成随机 Fourier 投影（fp32），既覆盖 fp16 buffer，又导致**每个 batch 投影不同、embedding 不可复现** | `load_fp16_model` 里把 12 个 FeatureMap 的 `deterministic` 强制置 True，改用 checkpoint 里已有的 `feature_map.weight`（已验证 12 层都在） |
| 10 | Morgan 全量内存爆炸风险 | 345 万×2048 float32 = 27 GB | 用 **uint8**（dense 6.9 GB）+ `np.packbits`（packed 0.86 GB）；`Pool.imap` 流式写入预分配数组，不建 345 万元素的 Python list |
| 11 | 每个脚本都重新解析 1.1 GB gz（51 s × N 次） | 无缓存 | 建 `smiles_all.parquet`，读取 0.8 s；`mol_io.load_smiles` 优先读缓存，缺失才回退解析 gz |

## 9. 全量资源估算（按实测速度外推，实际以日志里的 mol/s 与 ETA 为准）

| 任务 | 数据量 | 实测速度 | 预计耗时 | 显存 / 内存 | 输出体积 |
|---|---|---|---|---|---|
| MoLFormer（2 卡分片） | 3.45 M | ~1650 mol/s/卡 | **~20 分钟** | fp16 权重 ~94 MB；峰值未实测（估算 < 6 GB） | `(N,768)` fp16 = **5.3 GB**（每片 2.65 GB） |
